Khi triển khai workload trên **Google Cloud Platform (GCP)**, **Managed Instance Groups (MIGs)** là một trong những cách mạnh mẽ nhất để chạy các ứng dụng có khả năng **mở rộng (scalable)** và **chịu lỗi cao (resilient)**.

Trong khi **Stateless MIGs** phù hợp cho hầu hết các trường hợp, một số ứng dụng cần **lưu trữ trạng thái lâu dài (persistent state)** — đây chính là lúc **Stateful MIGs** được sử dụng.

---

# 🔹 Stateful MIG là gì?

**Stateful Managed Instance Group** là một loại MIG đặc biệt có khả năng **bảo toàn trạng thái riêng biệt của từng VM instance trong nhóm**.

Điều này có nghĩa là khi MIG thực hiện:

* auto-healing
* cập nhật (update)
* thay thế VM

thì nó vẫn có thể **giữ lại disk, metadata và địa chỉ IP**, đảm bảo tính liên tục cho các workload phụ thuộc vào dữ liệu riêng của từng instance.

### Các thành phần trạng thái được bảo toàn

* **Persistent Disks** (Boot Disk và Data Disk)
* **Instance Metadata**
* **Tên Instance có thể tùy chỉnh**
* **Địa chỉ IP nội bộ và IP công khai**

# 🔹 Các tính năng chính của Stateful MIG

⚡ **Load Balancing** – Phân phối lưu lượng truy cập giữa các instance

🌍 **Multi-zone Deployments** – Đảm bảo tính sẵn sàng cao trên nhiều zone

🩺 **Auto-healing (kèm Health Check)** – Thay thế instance không khỏe mà không mất trạng thái

🔄 **Auto-updating** – Cập nhật hệ thống mà vẫn giữ nguyên các tài nguyên trạng thái

💾 **Bảo toàn Disk và Metadata** – Giữ dữ liệu và cấu hình gắn với từng VM

⚠️ **Lưu ý:** Không giống Stateless MIG, **Stateful MIG không hỗ trợ Autoscaling**, vì việc tăng hoặc giảm số lượng instance có thể dẫn đến **mất trạng thái đã lưu**.

---

# 🔹 Khi nào nên sử dụng Stateful MIG?

Stateful MIG được khuyến nghị cho các ứng dụng **không thể hoạt động nếu không giữ trạng thái riêng của từng instance**, ví dụ:

🗄 **Cơ sở dữ liệu**
(MySQL, PostgreSQL, MongoDB, v.v.)

🏛 **Ứng dụng monolithic cũ (legacy)**
phụ thuộc vào storage cục bộ hoặc cấu hình tùy chỉnh

🕒 **Các tác vụ batch chạy lâu**
yêu cầu dữ liệu cục bộ được lưu trữ liên tục

# Instance Groups – Unmanaged vs Stateless MIG vs Stateful MIG

Khi làm việc với **Google Compute Engine**, bạn thường cần quản lý nhiều VM cùng lúc.
Đây là lúc **Instance Groups** được sử dụng.
![](https://media2.dev.to/dynamic/image/width=800%2Cheight=%2Cfit=scale-down%2Cgravity=auto%2Cformat=auto/https%3A%2F%2Fdev-to-uploads.s3.amazonaws.com%2Fuploads%2Farticles%2Fcht9h73w900kfh7nhi33.png)

Tuy nhiên, không phải tất cả instance group đều giống nhau. Bạn có thể chọn giữa:

* **Unmanaged Instance Groups**
* **Stateless Managed Instance Groups (MIG)**
* **Stateful Managed Instance Groups (MIG)**

tùy theo nhu cầu sử dụng.

---

# 🟦 1. Unmanaged Instance Groups

* Các VM **không cần giống nhau**
  (ví dụ: e2-small + e2-medium)

Chỉ hỗ trợ:

* **Load Balancing**

❌ Không hỗ trợ:

* Autoscaling
* Auto-healing
* Auto-updating
* Multi-zone deployment

Instance Template **không bắt buộc**.

⚠️ Không được khuyến nghị trừ khi bạn muốn **quản lý VM thủ công** hoặc chạy các VM **không đồng nhất** trong cùng một nhóm.

---

# 🟧 2. Managed Instance Groups – Stateless

Các VM **giống hệt nhau** và được tạo từ **Instance Template**.

Ví dụ:

* tất cả VM đều là **e2-small**

Hỗ trợ:

✅ Load Balancing
✅ Multi-zone deployment
✅ Autoscaling
✅ Auto-healing
✅ Auto-updating

Instance Template **bắt buộc**.

Được khuyến nghị trong **99% trường hợp sử dụng**, đặc biệt với các workload **stateless có thể scale ngang** như:

* web servers
* application servers

---

# 🟩 3. Managed Instance Groups – Stateful

Các VM **giống nhau**, nhưng **có thể giữ trạng thái riêng**.

Có thể bảo toàn:

* Persistent Disks (Boot + Data)
* Instance Metadata
* Internal IP
* External IP

Hỗ trợ:

✅ Load Balancing
✅ Multi-zone deployment
✅ Auto-healing
✅ Auto-updating

❌ Không hỗ trợ Autoscaling (để tránh mất trạng thái).

Instance Template **bắt buộc**.

Phù hợp cho các ứng dụng **stateful**, ví dụ:

* Database
* Ứng dụng monolithic legacy
* Tính toán lâu dài cần dữ liệu persistent

# Bước 02: Tạo Health Check

### Health Check là gì?

Health check xác định một **VM instance có hoạt động bình thường hay không** bằng cách gửi request đến instance.

Một instance được xem là **healthy** nếu nó trả về phản hồi liên tiếp trong thời gian quy định.

Health check được sử dụng cho:

* Load Balancing
* Autoscaling của managed instance groups

---

### Các bước trên Console

Vào:

```
Compute Engine → Instance Groups → Health Checks → CREATE HEALTH CHECK
```

Nhập:

* **Name:** app1-health-check
* **Description:**
* **Scope:** Regional
* **Region:** us-central1 (IOWA)
* **Protocol:** HTTP
* **Port:** 80
* **Proxy Protocol:** None
* **Request Path:** /index.html
* **Response:** App1
* **Host HTTP Header:** để trống
* **Logs:** Off (tránh chi phí Cloud Logging cao)
* **Health Criteria:** giữ mặc định

Nhấn **CREATE**.

---

### CLI tương đương

```bash
gcloud compute health-checks create http app1-health-check \
   --project=gcplearn9 \
   --port=80 \
   --request-path=/index.html \
   --proxy-header=NONE \
   --response=App1 \
   --region=us-central1 \
   --no-enable-logging \
   --check-interval=10 \
   --timeout=5 \
   --unhealthy-threshold=3 \
   --healthy-threshold=2
```

---

# Bước 03: Tạo Firewall Rule cho Health Check

Health check probe được gửi từ các dải IP:

```
130.211.0.0/22
35.191.0.0/16
```

Bạn cần đảm bảo firewall cho phép các IP này kết nối tới ứng dụng.

Trong ví dụ này:

* MIG sử dụng **default network**
* VM lắng nghe **port 80**

Nếu port 80 chưa mở, tạo firewall rule.

---

### CLI

```bash
gcloud compute firewall-rules create allow-health-check \
    --allow tcp:80 \
    --source-ranges 130.211.0.0/22,35.191.0.0/16 \
    --network default
```

# Bước 05: Tạo Stateful Managed Instance Group (Single Zone)

### Persistent Disks

Disk sẽ được bảo toàn trong suốt vòng đời VM.

Nó sẽ được:

* gắn lại khi VM được tạo lại
* gắn lại khi autohealing
* gắn lại khi update

và chỉ bị xóa khi instance bị xóa vĩnh viễn.

---

### Persistent Internal & External IP

IP cũng được bảo toàn trong suốt vòng đời VM.

---

### Tạo Managed Instance Group

Thông tin:

* **Name:** mig-stateful
* **Description:** mig-stateful
* **Location:** Single Zone
* **Region:** us-central1
* **Zone:** us-central1-a
* **Instance Template:** mig-it-stateful
* **Number of Instances:** 2

---

## Stateful Configuration

### persistent-disk-1

* **Device Name:** persistent-disk-1
* **Stateful:** YES
* **On permanent deletion:** Detach disk

Disk sẽ được:

* giữ lại khi VM được tạo lại
* giữ lại khi autohealing
* giữ lại khi update
* tách ra khi instance bị xóa

---

### External IP

* **Stateful:** YES
* **On permanent deletion:** Detach IP

---

### Internal IP

* **Stateful:** YES
* **On permanent deletion:** Detach IP

---

## VM Instance Lifecycle

Giữ mặc định.

**Action on failure:** Repair instance

---

## Autohealing

* **Health Check:** app1-health-check
* **Initial Delay:** 300 seconds

---

## Port Mapping

* **Port Name:** webserver-port
* **Port Number:** 80

Các tùy chọn nâng cao giữ mặc định.

Nhấn **CREATE**.

Vào:

```
Compute Engine → Instance Groups → mig-stateful
```

```

```

```
Compute Engine → Disks
```

