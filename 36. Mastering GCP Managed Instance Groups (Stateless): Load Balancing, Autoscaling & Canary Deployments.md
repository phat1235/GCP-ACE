## Google Compute Engine – Managed Instance Groups (Stateless)

**Managed Instance Groups (MIGs)** của Google Cloud là một trong những cách mạnh mẽ nhất để chạy các ứng dụng có khả năng mở rộng và độ tin cậy cao trên cloud. Chúng cho phép bạn quản lý nhiều máy ảo giống hệt nhau như một **đơn vị logic duy nhất**, với các tính năng như **autoscaling, load balancing, auto-healing và rolling updates**.

---

# 🔹 Managed Instance Groups (MIGs) là gì?

**Managed Instance Group (MIG)** là một tập hợp các VM instances giống hệt nhau được tạo ra từ cùng một **instance template**.

Với MIG, bạn **không quản lý từng VM riêng lẻ**. Thay vào đó, bạn quản lý **toàn bộ nhóm**.

* Nếu một VM bị lỗi → Google sẽ **tự động tạo VM mới để thay thế**.
* Nếu nhu cầu tăng → MIG **tự động mở rộng số lượng VM** để đáp ứng tải.

---

# 🔹 Vì sao sử dụng Stateless MIG?

**Stateless MIG** là cấu hình phổ biến nhất, trong đó tất cả VM đều giống nhau và **không lưu trạng thái dữ liệu riêng biệt**.

Các điểm chính:

* Tất cả VM được tạo từ **cùng một instance template**
* **Instance Template là bắt buộc**
* Được khuyến nghị cho **99% các trường hợp sử dụng**

# 🔹 Các tính năng của Stateless MIG

✅ **Load Balancing** – Phân phối lưu lượng truy cập đều giữa các VM

✅ **Multi-zone Deployments** – Tăng khả năng sẵn sàng bằng cách phân tán VM trên nhiều zone

✅ **Autoscaling** – Tự động scale in/out dựa trên CPU, tải hoặc metric tùy chỉnh

✅ **Auto-healing (Health Checks)** – Tự động thay thế các VM không khỏe

✅ **Auto-updating** – Rolling updates với thời gian downtime tối thiểu

![](https://media2.dev.to/dynamic/image/width=800%2Cheight=%2Cfit=scale-down%2Cgravity=auto%2Cformat=auto/https%3A%2F%2Fdev-to-uploads.s3.amazonaws.com%2Fuploads%2Farticles%2Fwsxzd6srtcv9xakzc12c.png)

# 🔹 Global MIG vs Regional MIG

📌 **Global MIG**

* Các instance được triển khai trên **nhiều region**
* Hoạt động với **Global HTTP(S) Load Balancer**
* Phù hợp cho **ứng dụng quy mô toàn cầu**

📌 **Regional MIG**

* Các instance được triển khai trên **nhiều zone trong cùng một region**
* Hoạt động với **Regional Load Balancer**
* Phù hợp cho **high availability trong một region**

# 🔹 Bước 02: Tạo Instance Template

Managed Instance Group yêu cầu **Instance Template**. Template này định nghĩa:

* loại máy (machine type)
* boot disk
* startup script
* các cấu hình khác của VM

## Các bước trên Console

Vào:

```
Compute Engine → Instance Templates → Create Instance Template
```

Nhập thông tin:

* **Name:** mig-it-stateless-v1
* **Location:** Regional (us-central1)
* **Machine Type:** e2-micro (Series E2)
* **Firewall:** Allow HTTP traffic
* **Service Account:** Default
* **Startup Script:** thêm script `v1-webserver-install.sh`

### Script khởi động

```bash
#!/bin/bash
sudo apt install -y telnet
sudo apt install -y nginx
sudo systemctl enable nginx
sudo chmod -R 755 /var/www/html
HOSTNAME=$(hostname)
sudo echo "<!DOCTYPE html> <html> <body style='background-color:rgb(250, 210, 210);'> <h1>Welcome to Latchu@DevOps - WebVM App1 </h1> <p><strong>VM Hostname:</strong> $HOSTNAME</p> <p><strong>VM IP Address:</strong> $(hostname -I)</p> <p><strong>Application Version:</strong> V1</p> <p>Google Cloud Platform - Demos</p> </body></html>" | sudo tee /var/www/html/index.html
```

Nhấn **Create** để lưu template.

# 🔹 Bước 03: Tạo Health Check

## Health Check là gì?

Health check xác định một VM có hoạt động tốt hay không bằng cách **gửi request định kỳ**.

* Nếu VM phản hồi đúng → **Healthy**
* Nếu VM không phản hồi → **Unhealthy**

MIG có thể **tự động restart hoặc thay thế VM**.

Health check cần thiết cho:

* Load balancing
* Autoscaling
* Auto-healing

---

## Các bước trên Console

```
Compute Engine → Instance Groups → Health Checks → Create Health Check
```

Nhập:

* **Name:** app1-health-check
* **Scope:** Regional
* **Region:** us-central1
* **Protocol:** HTTP
* **Port:** 80
* **Request Path:** /app1/status.html
* **Response:** App1
* **Proxy Protocol:** None
* **Logs:** Off
* **Health Criteria:** mặc định

Nhấn **Create**.

## CLI

```bash
gcloud compute health-checks create http app1-health-check \
   --project=gcpdemos \
   --port=80 \
   --request-path=/index.html \
   --proxy-header=NONE \
   --response=Welcome \
   --region=us-central1 \
   --no-enable-logging \
   --check-interval=10 \
   --timeout=5 \
   --unhealthy-threshold=3 \
   --healthy-threshold=2
```

* **Targets:** All instances
* **Source ranges:**


* **Protocols and ports:** tcp:80

Nhấn **Create**.

```bash

    --allow tcp:80 \
```

# Auto-Healing

MIG đã có khả năng **tự tạo lại VM khi VM crash**.

Nhưng nếu:

* ứng dụng bị freeze
* crash
* overload

VM vẫn RUNNING nhưng app không hoạt động.

Auto-healing dùng **health check của ứng dụng** để phát hiện lỗi.

Nếu health check fail → MIG **tự tạo lại VM**.

* phát hiện instance thiếu
* **tự tạo VM mới**

Đây là cơ chế **self-healing**.

# 🔹 Bước 14: REMOVE FROM GROUP

Khác với delete:

**Remove from Group**

* tách VM khỏi MIG
* không xóa ngay

Sau đó bạn có thể **giữ VM để debug**.

* không tạo VM mới

* tạo VM mới

Dùng khi:

* update instance template
* nâng cấp cấu hình VM

# Canary Deployment

**Canary Deployment** là:

* thử nghiệm version mới trên **một phần instance**
* trước khi rollout toàn bộ

Ví dụ:

* 50% instance chạy V1
* 50% instance chạy V2

Nếu ổn → rollout toàn bộ.
