**Phần 35: 🚀 Triển khai Unmanaged Instance Group với Load Balancer trên Google Cloud Platform (GCP)**

#googlecloud
#devops
#cloud
#tutorial

Khi chạy workload trên **Google Cloud Platform (GCP)**, việc quản lý các **VM instance theo nhóm** giúp phân phối lưu lượng truy cập và tăng độ tin cậy của hệ thống. Mặc dù **Managed Instance Groups (MIGs)** thường được khuyến nghị, nhưng trong một số trường hợp bạn có thể muốn sử dụng **Unmanaged Instance Groups (UMIGs)** để **tự quản lý các VM không giống nhau**.

Trong hướng dẫn này, chúng ta sẽ thực hiện:

* Tạo **Unmanaged Instance Group**
* Gắn **Health Check**
* Tạo **Firewall Rule**
* Xuất bản dịch vụ thông qua **Load Balancer**

---

# 🔹 Unmanaged Instance Group là gì?

* Cho phép các **VM không giống nhau** trong cùng một nhóm (ví dụ: e2-micro + e2-small).
* Hỗ trợ **load balancing**.

❌ Không hỗ trợ:

* Autoscaling
* Auto-healing
* Rolling updates
* Triển khai đa zone

Không yêu cầu **Instance Template**.

⚠️ **Không khuyến nghị dùng cho môi trường production**, trừ khi bạn muốn tự quản lý VM.

---

# 🛠️ Bước 01: Chuẩn bị và giới thiệu

Chúng ta sẽ tạo:

* Hai VM chạy **Nginx**
* Một **Unmanaged Instance Group**
* **Health Check** và **Firewall Rule**
* Một **HTTP Load Balancer**

Cuối cùng kiểm tra việc **phân phối lưu lượng giữa các VM**.

Trước tiên hãy đảm bảo có file **webserver-install.sh** trong Cloud Shell:

```bash
#!/bin/bash
sudo apt install -y telnet
sudo apt install -y nginx
sudo systemctl enable nginx
sudo chmod -R 755 /var/www/html
HOSTNAME=$(hostname)
sudo echo "<!DOCTYPE html> <html> <body style='background-color:rgb(250, 210, 210);'>
<h1>Welcome to Latchu@DevOps - WebVM App1</h1>
<p><strong>VM Hostname:</strong> $HOSTNAME</p>
<p><strong>VM IP Address:</strong> $(hostname -I)</p>
<p><strong>Application Version:</strong> V1</p>
<p>Google Cloud Platform - Demos</p>
</body></html>" | sudo tee /var/www/html/index.html
```

# Bước 03: Tạo Unmanaged Instance Group

Vào:

**Compute Engine → Instance groups → Create a new Unmanaged Instance group**
![](https://media2.dev.to/dynamic/image/width=800%2Cheight=%2Cfit=scale-down%2Cgravity=auto%2Cformat=auto/https%3A%2F%2Fdev-to-uploads.s3.amazonaws.com%2Fuploads%2Farticles%2Fhjh2om6vtu1xlyxt3tlu.png)
Thiết lập:

* Name: **umig-1**
* Description: **unmanaged-instance-group-1**
* Location: **us-central1 (IOWA)**
* Zone: **us-central1-a**
* Network: **default**
* Subnetwork: **default**
* VM Instances: **vm1, vm2**

Specify Port Name Mapping:

* Port Name: **webserver-port**
* Port Numbers: **80**

Nhấn **CREATE**

---

## CLI

```bash
# Create UMIG
gcloud compute instance-groups unmanaged create umig-1 \
   --zone=us-central1-a \
   --description=unmanaged-instance-group-1

# Add named port for HTTP
gcloud compute instance-groups unmanaged set-named-ports umig-1 \
   --zone=us-central1-a \
   --named-ports=webserver-port:80

# Add VMs to UMIG
gcloud compute instance-groups unmanaged add-instances umig-1 \
   --zone=us-central1-a \
   --instances=vm1,vm2
```

# Bước 05: Tạo Health Check

**Health Check là gì?**

Health Check xác định **VM instance có hoạt động bình thường hay không** bằng cách gửi các request kiểm tra.

Một instance được coi là **healthy** nếu trả về phản hồi đúng trong khoảng thời gian xác định.

Health Check được sử dụng cho:

* Load Balancing
* Autoscaling trong Managed Instance Groups

Tạo Health Check:

**Compute Engine → Instance Groups → Health Checks → CREATE HEALTH CHECK**

Thiết lập:

* Name: **app1-health-check**
* Scope: **Regional**
* Region: **us-central1 (IOWA)**
* Protocol: **HTTP**
* Port: **80**
* Proxy Protocol: **None**
* Request Path: **/index.html**
* Response: **Welcome**
* Host HTTP Header: để trống
* Logs: Off (nếu bật sẽ tốn chi phí Cloud Logging)
* Health Criteria: để mặc định

---

## CLI

```bash
# Create Health Check
gcloud compute health-checks create http app1-health-check \
   --project=gcpdemos \
   --port=80 \
   --request-path=/index.html \
   --proxy-header=NONE \
   --response=Welcome \
   --region=us-central1 \
   --no-enable-logging \
   --check-interval=10 \
   --timeout=5 \
   --unhealthy-threshold=3 \
   --healthy-threshold=2
```

---

# Bước 06: Tạo Firewall Rule cho Health Check

Các probe của Health Check đến từ các dải IP:

* **130.211.0.0/22**
* **35.191.0.0/16**

Cần cho phép các địa chỉ này truy cập ứng dụng.

```bash
# Create Firewall rule
gcloud compute firewall-rules create allow-health-check \
    --allow tcp:80 \
    --source-ranges 130.211.0.0/22,35.191.0.0/16 \
    --network default
```

# Bước 07: Tạo Load Balancer

Vào:

**Network Services → Load Balancing → Create Load Balancer**

Chọn:

**HTTP(S) Load Balancing → START CONFIGURATION**

Thiết lập:

* Internet facing or internal only: **From internet to my VMs**
* Deployment: **Single Region**

Name: **lb-for-umig1**

⚠️ Nhấn **RESERVE SUBNET**

* Name: **proxy-only-subnet**
* IP Address: **10.0.0.0/24**

Nhấn **CREATE**

---

## Frontend Configuration

* Name: **fip-lb-umig**
* Protocol: **HTTP**
* Network Service Tier: **Premium**
* IP Version: **IPv4**

Tạo IP:

* Name: **sip-lb-umig**
* Description: **sip-lb-umig**

Port: **80**

Nhấn **DONE**

---

## Tạo Backend Service

* Name: **lb-backend-umig**
* Backend Type: **Instance Group**
* Protocol: **HTTP**
* Named Port: **http**
* Timeout: **30**

Backend:

* Instance group: **umig-1**

Thiết lập:

* Port: **80** (webserver-port)
* Balancing mode: **Utilization**
* Maximum backend utilization: **80**
* Scope: **per instance**
* Capacity: **100**

Cloud CDN: để trống
Health Check: **app1-health-check**
Logging: để trống
Security: để trống

Nhấn **CREATE**

---

## Host and Path Rules

Mode: **Simple host and path rule**

Kiểm tra lại:

* Frontend
* Backend

Nhấn **CREATE**

Quá trình tạo Load Balancer mất khoảng **3–5 phút**.

# Bước 09: Truy cập ứng dụng thông qua IP của Load Balancer

```
http://<LB-IP-ADDRESS>
```

Ví dụ:

```
http://35.209.128.93
```

Quan sát:

1. Refresh trang nhiều lần để thấy phản hồi từ cả hai VM.
2. Nội dung sẽ **luân phiên giữa các VM**.

# Bước 10: Dọn dẹp – Xóa Load Balancer

Vào:

**Network Services → Load Balancing → lb-for-unmanaged-instance-group**

Nhấn **DELETE**

Chọn xóa:

* Backend services: **lb-backend-umig**

Không chọn:

* **Health Checks: app1-health-check**

Nhấn **DELETE LOAD BALANCER AND SELECTED RESOURCES**
